# finance 30 道题模型试跑：操作说明

每个对话一个文件夹，共 19 个：01 至 12 各一个，另外 7 条链各一个（13-15、16-18、19-21、22-23、24-25、26-27、28-30）。

每个文件夹里有：
- `第NN题_发送内容.md`：要发给模型的全文。内容是题面，末尾加三行：附件在哪个文件夹、前几轮的成果在哪、本题文件存到哪。
- `第NN题_附件/`：该题的题目附件。和收题表上的题目附件逐个一致，不含标准答案、标准答案附件和考点。
- `产物/第NN题/`：让模型把交付文件存在这里。
- `导出/`、`截图/`：跑完后放导出的 trace 和截图。
- `.kiro/settings/mcp.json`：已经配好 US Stocks MCP（https://mcp-stocks-us.gino.im/mcp）。

## 开始前（每个对话做一次）

1. 在 Kiro 里用 File → Open Folder 打开这个对话的文件夹，单独开一个窗口。不要在 `expert-question` 仓库里跑，那里有标准答案。
2. 打开 MCP 面板，确认 `us-stocks` 已连接。
3. 新开一个聊天：
   - 模型选 Claude Opus 5.5。
   - Effort 拉到最高档，有 max 就选 max，没有就选 xhigh 或 high。会议要求 High 以上，优先最高档。
   - 打开 Autopilot，模型中途就不会停下来等确认。
4. 整个对话里不要用 /compact。压缩会改掉 trace。

## 跑的时候

- 打开 `第NN题_发送内容.md`，全文复制，粘贴发送，等模型做完。
- 多轮题（同一条链）在同一个聊天里接着发下一题的发送内容。不要新开聊天。
- 模型提问时，只回「请按题面和附件自行判断」。不提示，不纠正，不补充材料。
- 模型把文件存到了别处的，等这一轮结束，手工挪进 `产物/第NN题/`。只挪位置，不改内容。
- 题面写的 MCP 查询，必须在对话里通过 MCP 实际调用。模型说 MCP 不可用、改用 Python 直接请求接口的，这一次不算：先检查 MCP 面板，重新连上以后整个对话重跑。

## 跑完以后

1. 在聊天标签上点右键，选 Export Chat，把 zip 存进这个对话的 `导出/`。
2. 截完整对话，从第一条消息截到最后一条。按顺序命名为 `01.png`、`02.png`……，存进 `截图/`。
3. 在仓库里核对并整理：

   ```bash
   cd ~/workspace/expert-question/finance/_工具
   python3 试跑.py check     # 核对：模型和档位、每一轮是否真的调用了 MCP、产物、截图、有没有碰到仓库或标答
   python3 试跑.py collect   # 核对通过的对话，整理成 ~/workspace/finance-试跑/交付/
   ```

   `check` 报的问题要处理完。比如漏了 MCP 调用，就整个对话重跑。

`交付/<题号>_<名称>/` 里放的是收题表要的四样，另附 Kiro 导出的原件：

| 文件 | 对应字段 |
| --- | --- |
| `模型回复.md` | 模型回复。取 trace 里这一轮模型的正文，不含思考过程。取不到时，手工把正文存成对话文件夹里的 `回复/第NN题.md`，再跑一次 collect |
| `模型产物.zip` | 模型产物附件，打包的是 `产物/第NN题/` |
| `模型运行Trace.json` | 模型运行 Trace，把导出 zip 里的 session.json 和 messages.jsonl 原样合进一个 JSON |
| `Kiro导出原件_*.zip` | 导出原件，备查 |
| `模型运行截图/` | 模型运行截图 |

同一条链的几道题，用的是同一份 trace 和同一组截图。
