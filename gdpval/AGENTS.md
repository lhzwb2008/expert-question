# GDPval 出题：给 agent 的工作说明

这份是 `gdpval/` 的总说明，写给在 Cursor 里接手 GDPval 试标的 agent。用户用中文交流。规则来自 2026-11-13 读过的《GDPval 专家标注作业 SOP》和《GDPval答疑&培训表》，以及当天已经填进工作台、尚未提交的试标。

工作台地址、登录 token、录屏密码都不写进仓库。打不开时，用电脑上已经登录智囊团的 Chrome，不要另开账号。

## 用户的固定要求

- 全程用中文回复。
- Gold Answer 必须用户本人做。agent 不生成、不代写、不上传标准答案，也不要把标答数字写进题干、参考文件或评分点。
- 用户说「填」只填到可检查的草稿。说「提交」之前，不调用提交接口，不点「提交出题」。
- 参考文件按业务材料准备。正文不出现「本题」「出题」「评分点」「标准答案」。
- 任务包必须是【GDPval-9领域-C端专家任务-1103】。看到别的包不要在里面新建。

## 这个项目在收什么

给垂类岗位做真实工作评测。一条数据是专家自己的业务任务，不是公开题的改写。平台是 `gdpval.tlabel.tencent.com`，任务包 id 是 `PKG-844865`，类型是非搜索（`non_search`）：参考材料必须够用，模型不能联网。

专家负责四段：待出题、Rubrics 生成、出题专家校验、专家待跑分。后面的通用质检、专业质检、终审不是这个账号的活。

一条完整数据有六项：

| 交付 | 内容 | 合格看什么 |
| --- | --- | --- |
| Task Prompt | 一段任务委托 | 同岗位的人不用再问就能做 |
| Reference File | 完成任务需要的附件；没有就明确写无 | 打得开、相关、已脱敏、时间线一致 |
| Gold Answer | 专家本人做的交付物 | 能交给客户或领导，能复核 |
| Rubrics | 可二元判断的评分点 | 原则上不少于 20 条，满足下面六项标准 |
| 元数据 | 行业、岗位、任务类型、难度、交付物类型 | 字段彼此一致，并和题干里的角色一致 |
| 跑分 | 平台指定模型的结果 | HY4 低于 60 分才可以交质检 |

最高红线：Gold Answer 不许 AI 生成、代做或批量合成；不许虚构数据、法规和事实。

金融与投资财经在这包里的配额是 17 题，九个领域合计 200 题，整包截止 2027-01-30。新人培训后 T+3 内交 1 条试标，有 3 次返修，两周内改完；试标不过就汰换。质检反馈按 T+2。这条试标就是那 1 条。

岗位用下拉里的标准名。金融与投资财经有：信贷审核专业人员、证券投资专业人员、公司金融顾问、保险核保专业人员、证券保荐承销专业人员、公司财务人员。题干里的角色必须和下拉是同一个岗位。答疑表里已经有人因为下拉选了信贷审核、题干写成财务报告审核员被指出有问题；只改岗位、不改题干时，不必重跑模型产物。

证券投资专业人员的建议方向是投研报告和估值分析，典型交付是研究报告（Word 或 PDF）加测算表（Excel）。方向可以扩展，但不能改成五分钟问答。

## 自动执行：已跑通的填法

浏览器代填不必做。2026-11-13 用工作台自己的接口填完了草稿。接口根路径是 `https://gdpval.tlabel.tencent.com/api`。

### 1. 拿登录

账号是电脑上 Chrome 默认配置里已经登录的智囊团，不要扫新的码。用该配置的 Cookie 请求：

```
GET https://tlabel.tencent.com/api/v1/kits/sso/jump?target=gdpval-label
```

跟着跳转走，停在带 `token=` 的地址上，取出 token。之后每个请求带 `Authorization: Bearer <token>`。先 `GET /auth/me`，确认 `username` 是 Wenbo、`role` 是 expert。401 就重新要一次 token。

Cookie 的解法：Chrome 130 以上（本机库版本 24）是 `v10` + AES-128-CBC，密钥由钥匙串「Chrome Safe Storage」经 PBKDF2-HMAC-SHA1（盐 `saltysalt`、1003 次、16 字节）导出，IV 是 16 个空格。解密后再去掉开头 32 字节的 `SHA-256(host_key)`。token 和 Cookie 只放临时文件，不进仓库，用完删掉。

### 2. 确认任务，不要重复新建

`GET /packages` 里只有这一包时，核对接包名和 `packageType=non_search`。专家角色 `GET /tasks` 会 403，改 `GET /tasks/<taskId>`。

`PKG-844865-709` 还是「待出题」时，接着填它，不要 `POST /tasks` 再开一条。用户明确要新的一条、且 709 已经提交或废弃时，才创建：

```
POST /tasks
{"packageId":"PKG-844865","industry":"金融与投资财经","occupation":"证券投资专业人员"}
```

创建只带这三个字段，任务类型会默认成 `file-in/file-out`，难度默认 L2。

### 3. 写元数据

```
PATCH /tasks/<taskId>/authoring-classification
```

字段：`industry`、`occupation`、`taskType`、`deliverableType`、`explicitDifficulty`。`deliverableType` 用英文逗号拼接，顺序和界面多选一致，例如 `Word,Excel`。可选值是 Excel、Word、PDF、PPT、文本。任务类型只有四种：`file-in/file-out`、`file-in/text-out`、`text-in/file-out`、`text-in/text-out`。难度是 L1、L2、L3、L4。

这个接口返回 200 时正文不一定带回字段。以随后的 `GET /tasks/<taskId>` 为准。

### 4. 写题干草稿

题干不在任务的 `taskPrompt` 里，那个字段要等用户提交才写入。未提交的内容在草稿：

```
PUT /tasks/<taskId>/draft
{"scope":"authoring","payload":{
  "prompt":"<题干全文>",
  "industry":"金融与投资财经",
  "occupation":"证券投资专业人员",
  "taskType":"file-in/file-out",
  "deliverable":"Word,Excel",
  "difficulty":"L3",
  "goldText":""
}}
```

`GET /tasks/<taskId>/draft?scope=authoring` 对一下 `payload.prompt`。页面打开时优先用云端草稿，所以用户刷新后应看到这段题干。`goldText` 保持空字符串。

### 5. 上传参考文件

```
POST /tasks/<taskId>/files
```

`multipart/form-data` 两个字段：`file` 是文件，`file_role` 是 `reference`。标准答案才会用 `gold_answer`，agent 不用这个值。

接受的扩展名：`.docx` `.doc` `.xlsx` `.xls` `.pptx` `.ppt` `.pdf` `.txt` `.md`。不接受 `.csv` 和 `.json`。表格转 xlsx，说明留 md。用带 pandas 和 openpyxl 的解释器：`/opt/homebrew/bin/python3.13`。

删错文件：`DELETE /files/<fileId>`。id 从任务的 `referenceFiles` 取。

传完再 GET 任务：状态仍是「待出题」，`referenceFiles` 的文件名和本地一致，`goldAnswers` 为空。

### 6. 停在这里

不要 `POST /tasks/<taskId>/submit-authoring`。那个接口会生成 Rubrics，并把题目送出待出题。用户要先看题干和九份文件，自己做完 Gold 并上传，再自己点「提交出题」。

提交被挡住是对的，少了 Gold 就该灰。不要为了把按钮点亮去做一份标准答案。

## 出题规则

### 选题

四条都要满足：这个岗位真实会做；做完能收费或能向上级交付；一名同岗位的人能独立做完；结果能用材料、计算或规则复核。要有专业判断，不能五分钟做完。

排除：名词解释，没有对错的讨论，依赖私有系统、付费库或实时内部数据，必须线下才能验证，以及政治敏感、违规、未脱敏的内容。

旧项目里能直接改成这一包的，是材料已经闭卷、交付物是文档加表格的研究或测算。需要当场调用 MCP 的版本先把查询结果冻结进附件，再改成「使用所附导出」，不能在题干里留一个让模型去访问的地址。

同一套附件不要交第二次。Magnet 和金融收题表用过的恒指材料，这条试标已经用了。

### 题干

六段都要有，写成一段：角色和场景、每份附件的文件名和用途、要做的判断或计算、内容要求、边界、交付物的格式和文件名。文件名和上传的文件逐字一致。

可以写角色、范围、材料关系和交付名称。不可以写结论、名单、金额、净收益和「正确做法是哪一种」。规则文件里已经有的门槛，不要在题干里再演算一遍。

材料不够时，允许保留已确认事实、标出待核和对结论的影响。不允许编价格把缺口补上。

### 参考文件

每份文件都要同时被三处用到：模型完成任务要用，Gold 会用到，评分点会考到。三处都用不到就删。必须用却没给，就是缺件。

脱敏：姓名、电话、证件、账号、住址换成不可回推的占位；主体用「A 公司」这类叫法；改过的数字要同时改 Gold 和评分点。上传后逐个打开，排除空白、损坏和旧版本。

非搜索题的全部事实都在题干和附件里。附件里的规则写业务规则本身，不写解题步骤，不点名哪一份是干扰。

### Gold

用户按锁定的题干和附件，做成可以交出的成品。文件名用交付物的名字，例如《恒指调整开展建议》，不要叫「专家答案」或「Gold」。Word 看文书是否完整，Excel 的公式要能重算，数字和附件一致。要求 docx 就不要交 xlsx。

### 提交之后才会发生的事

用户提交后，系统用题干和 Gold 生成候选评分点。agent 如果被要求接着做，按这个顺序，仍然不要改 Gold：

1. 等生成结束。失败会退回待出题，先看代理或模型配置，不要连点提交。
2. 出题专家校验：先点一键质检。质检意见只作参考。评分点的描述、权重、类型、维度错了，改对应列。只有确认是生成机制本身的问题，才写 PE 问题反馈。把错误评分点写进反馈列、却不改正文，是错的。
3. 题干或附件要改，打回待出题，改源文件，五处一起对：题干、参考文件、Gold、评分点、元数据。
4. 评分点原则上不少于 20 条。六项标准是：正确、互斥、完备、原子、客观、自包含。一条只考一个点，读这一条就能判断对或错，并写明正确值或区间。不要用「合理、专业、充分、准确」。内容质量的权重要高于格式。同一考点不要计两次。评分点不能超出题干，也不能要求 Gold 自己没做到的事。
5. 权重按业务后果。核心结论和关键计算高，一般信息中低，单项格式低。编造数据、文件打不开、缺交付物重罚。内容质量里，一般点 1 到 3 分，核心点 4 到 7 分；局部错误 -1 到 -3，关键错误 -4 到 -7，任务失败或伪造 -8 到 -10。
6. 专家待跑分：点一键生成全部，再一键判分全部。产物模型只能是 HY4。没有 HY4，或多了别的模型，新建一条任务，不要在这条上改模型清单。判分后逐条复核，勾选是命中，不勾是未命中；改了命中或权重，在备注写原因。
7. HY4 低于 60 分，才提交通用质检。不低于 60，按这个顺序查：题干是否太简或把答案说漏了，附件是否直接含答案，Gold 是否按题干做全，评分点是否漏考点或放得太松，模型能否不经专业过程就猜到结论。禁止为了压分加假要求。
8. 终检清单还写了 HY 不应是得分最高的模型。这条包如果只跑 HY4，以 60 分那条为准；出现第二个模型，按第 6 步新建任务。

被打回时，平台意见会写在任务上。异议发到群里，格式是「题目 id：PKG-xxxxx-xxxx」加问题描述。

### 联动

改了题干，看 Gold 和评分点还盖不盖得住。改了附件里的主体、金额或日期，看 Gold 的引用和评分点里的正确值。改了 Gold 的结论或计算，看评分点的判定值。改了评分点，看有没有超出题干、Gold 还能不能拿满该拿的分、要不要重跑。改了格式或份数，看题干、交付物类型和实际上传的文件。
